Top 9 HTTP Methods You Must Know as a Web Developer 👇

If you work with web development or APIs, you’ll use HTTP request methods all the time. Each method instructs the server on the action you want it to take.

Let’s go through them step by step 👇

[1.] GET → Retrieves data from the server.
◾ Think of it like reading a book — you only view the pages, you don’t change anything.

[2.] POST → Sends new data to the server.
◾ Like adding a new contact to your phone.

[3.] PUT → Updates a resource completely.
◾ Imagine replacing an old note with a new one.

[4.] PATCH → Updates part of a resource.
◾ Like fixing one line in your note instead of rewriting everything.

[5.] DELETE → Removes a resource from the server.
◾ Once it’s gone, it stays gone — even if you repeat the request.

[6.] OPTIONS → Asks the server what actions are allowed.
◾ Like checking a restaurant menu before ordering.

[7.] HEAD → Similar to GET, but it only returns headers (no full content).
◾ Like looking at a book cover without opening it.

[8.] TRACE→ Used to test or debug the connection.
◾ It shows how your request travels through the network.

[9.] CONNECT → Creates a direct tunnel between your device and the server.
◾ Often used for secure (HTTPS) connections.

𝟭. 𝗖𝗮𝗹𝗹 𝗦𝘁𝗮𝗰𝗸
 - 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗶𝘁?
 The Call Stack is where JavaScript keeps track of function calls. It is a stack structure that handles synchronous code execution.
 - 𝗛𝗼𝘄 𝗱𝗼𝗲𝘀 𝗶𝘁 𝘄𝗼𝗿𝗸?
1. When a function is invoked, it’s pushed onto the stack.
2. Once it finishes, it’s popped off.
3. If an error occurs during execution, it’s thrown from the stack.

𝟮. 𝗘𝘃𝗲𝗻𝘁 𝗤𝘂𝗲𝘂𝗲 (𝗖𝗮𝗹𝗹𝗯𝗮𝗰𝗸 𝗤𝘂𝗲𝘂𝗲)
 - 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗶𝘁?
 The Event Queue (also known as the callback queue) stores events that are to be processed asynchronously, like events triggered by a setTimeout or DOM events.
 - 𝗛𝗼𝘄 𝗱𝗼𝗲𝘀 𝗶𝘁 𝘄𝗼𝗿𝗸?
1. When the Call Stack is empty, the Event Loop checks the Event Queue.
2. It then pushes the next task onto the stack for execution.


𝟯. 𝗠𝗶𝗰𝗿𝗼𝘁𝗮𝘀𝗸 𝗤𝘂𝗲𝘂𝗲
 - 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗶𝘁?
 The Microtask Queue holds tasks that need to be executed after the currently executing script, but before any events in the event queue. Microtasks include promise callbacks and other tasks like MutationObserver.
 - 𝗛𝗼𝘄 𝗱𝗼𝗲𝘀 𝗶𝘁 𝘄𝗼𝗿𝗸?
 Once the call stack is empty and before the event queue is processed, the event loop picks up and processes tasks in the microtask queue. This ensures that promises are resolved before other events are processed.

𝟰. 𝗘𝘃𝗲𝗻𝘁 𝗟𝗼𝗼𝗽
 - 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗶𝘁?
 The Event Loop is the mechanism that allows JavaScript to perform non-blocking operations by managing the order in which tasks are executed from the call stack, event queue, and microtask queue.
- 𝗛𝗼𝘄 𝗱𝗼𝗲𝘀 𝗶𝘁 𝘄𝗼𝗿𝗸?
 The event loop constantly checks the call stack. If the call stack is empty, it checks the microtask queue and processes any pending microtasks. After all microtasks are processed, the event loop picks events from the event queue for execution.

𝗞𝗲𝘆 𝗣𝗼𝗶𝗻𝘁:
 Microtasks are always executed before the event queue. This is why Promise.then() is processed before setTimeout().

𝟱. 𝗦𝗲𝘁𝗧𝗶𝗺𝗲𝗼𝘂𝘁 𝗮𝗻𝗱 𝗦𝗲𝘁𝗜𝗻𝘁𝗲𝗿𝘃𝗮𝗹
 - 𝗪𝗵𝗮𝘁 𝗶𝘀 𝗶𝘁?
 setTimeout() and setInterval() are used to schedule code execution after a specified time, but they are added to the event queue and are processed after all synchronous code and microtasks.
- 𝗛𝗼𝘄 𝗱𝗼𝗲𝘀 𝗶𝘁 𝘄𝗼𝗿𝗸?
 The setTimeout() and setInterval() tasks are executed after the current script is finished executing, which is why you may see asynchronous code run after synchronous code (even if it's scheduled for immediate execution).

As an Angular developer, it’s important to understand how Client-Side Rendering (CSR) works and where it fits best in modern web applications.

🔹 What is Client-Side Rendering?
CSR means the browser loads a minimal HTML file first, and Angular takes over to render the UI using JavaScript.

✅ How Angular bootstraps the application
✅ Role of index.html and root component
✅ Lazy loading modules for better performance
✅ Change detection & component lifecycle
✅ Routing in CSR
✅ API calls and data rendering
✅ State management (NgRx / Services)
✅ Performance optimization techniques
✅ SEO challenges in CSR
✅ Difference between CSR vs SSR

💡 When to use CSR?
✔ Dashboards
✔ Admin panels
✔ Internal tools
✔ Apps where SEO is not a priority

Faster UI interactions
